# Дизайн: Финансовая консультация и разбор состояния

**Дата:** 2026-07-17
**Статус:** согласован (брейншторм), готов к плану реализации
**Продукт:** «Баланс» (рабочее название) — веб-версия

---

## 1. Контекст и цель

Продукт развёрнут с трекера финансов на **фин-консультацию**: человек загружает
банковскую выписку и получает разбор своего финансового состояния, риски и
персональные рекомендации, плюс советник, которому можно задать вопрос про свои
деньги. Уже есть рабочий веб-прототип одноразового разбора (`prototype/app.html`)
и лендинг (`prototype/index.html`).

Эта итерация добавляет к разовому разбору **историю и память**: периодический
чек-ап с динамикой фин-здоровья и советник, который ссылается на прошлые разборы.

## 2. Принятые решения (из брейншторма)

- **Сценарий использования:** периодический чек-ап + постоянный советник с памятью.
  Не ежедневный трекинг — человек возвращается раз в период, загружает свежую
  выписку, видит динамику и прогресс по рекомендациям.
- **Границы советов:** бытовые финансы (траты, экономия, подушка, бюджет, долги)
  + образовательный ликбез про накопления/вклады. **Без персональных
  инвестиционных рекомендаций** (регулируемая территория).
- **Мозг советника:** правило-основанный — детерминированные ответы, считаемые из
  данных. Без бэкенда и LLM на этом этапе.
- **Подход к реализации:** A — клиентский MVP с локальной историей (снимки в
  localStorage), логика разбора и советника вынесена в изолированное «ядро» для
  задела под бэкенд (подход B) в будущем.

## 3. Объём и non-goals

**В объёме (MVP):**
- Загрузка выписки (CSV) или демо → разбор фин-состояния.
- Сохранение каждого разбора как датированного снимка (локально).
- Экран «Разбор»: score фин-здоровья 0–100, метрики, структура трат, риски,
  рекомендации.
- Экран «Динамика»: изменение score / расхода / нормы сбережений по снимкам,
  прогресс по рекомендациям.
- Советник (правило-основанный): отвечает по текущему разбору и ссылается на историю.
- Лёгкий локальный профиль: имя, список снимков, тема.

**Явные non-goals:**
- Не трекер: нет ежедневного ручного ввода операций, бюджетов-лимитов, семейного
  бюджета, целей-копилок как ядра продукта.
- Не персональные инвест-рекомендации (только общий ликбез).
- Не бэкенд / аккаунты / синхронизация на этом этапе (задел под B — позже).
- Не банковская интеграция (только загрузка файла пользователем).

## 4. Экраны

1. **Вход** — загрузка выписки (CSV, drag&drop / файл) или демо.
2. **Разбор** — результат: score + вердикт, метрики (норма сбережений, подушка в
   месяцах, доля необязательных трат, доход/расход/остаток), «куда уходят деньги»,
   риски и наблюдения, приоритизированные рекомендации, чат-советник.
3. **Динамика** — история снимков: серии score / расход-мес / норма сбережений по
   датам, дельты между последними двумя разборами, прогресс по отмеченным
   рекомендациям.
4. **Советник** — чат внутри разбора; ссылается на историю снимков.
5. **Профиль/настройки** — список снимков (открыть/удалить/экспорт), имя, тема.

## 5. Данные и хранилище

Всё в localStorage, без сервера.

- `profile` → `{ name, theme }`
- `snapshots` → массив датированных снимков:
  `{ id, date, period, source: "csv"|"demo", analysis, recDone: { [recId]: bool } }`
  - `analysis` — готовый результат разбора (см. §6), сериализуемый.
- Операции над снимками: создать, открыть, удалить, экспортировать (JSON).

## 6. Ядро разбора — `analyzer.js` (чистый модуль, без DOM)

**Вход:** транзакции `[{ ts, amount, desc }]` (из CSV или демо).

**Шаги:**
1. Категоризация по описанию (правила) + отделение внутренних переводов
   (перевод на вклад/себе/пополнение брокерского и т.п. — не считаются тратой/доходом).
2. Агрегаты: доход/мес, расход/мес, норма сбережений, подушка (месяцев),
   доля необязательных трат, топ-категории.
3. Score фин-здоровья 0–100 — взвешенная сумма факторов: норма сбережений,
   подушка, доля необязательных трат, «живёшь в ноль».
4. Риски (флаги) + рекомендации (приоритизированные, с суммами в рублях) +
   суммарный потенциал экономии.

**Выход:** объект `analysis` — чистые данные (метрики, категории, риски,
рекомендации, сырые агрегаты). Детерминированный, тестируемый, не зависит от UI.
Тот же контракт вход/выход позже переносится на бэкенд (подход B) без переписывания.

## 7. Советник — `advisor.js` (чистый модуль)

**Вход:** текущий `analysis` + история снимков.

- Интенты по ключевым словам: сэкономить, подушка, отложить, куда уходят,
  накопить на сумму, долги/кредиты, инвестиции/накопления.
- Ответы считаются из `analysis`; где уместно — сравнение с прошлым снимком
  («score вырос с 52 до 57», «на такси стал тратить меньше»).
- Инвестиции/накопления: общий образовательный ликбез с дисклеймером, без
  персональных рекомендаций конкретных бумаг/активов.
- Фолбэк: подсказать доступные темы вопросов.

## 8. Границы модулей (задел под бэкенд B)

- `analyzer.js` — расчёты, чистые функции.
- `advisor.js` — логика ответов, чистые функции.
- `store.js` — единственное место работы с хранилищем; позже подменяется на
  API-клиент без правок ядра/UI.
- `ui.js` — только рендер экранов, дёргает ядро и стор.
- Правило: UI сам финансы не считает, ядро не знает про DOM, стор изолирован.

## 9. Крайние случаи и обработка ошибок

- Кривой CSV / колонки не распознаны → понятная ошибка + подсказка формата
  (дата · сумма · описание) + кнопка «демо».
- Мало данных (< ~месяца / мало операций) → пометка «разбор ориентировочный»,
  часть метрик (подушка, динамика) неполны.
- Дохода нет в выписке → не показывать вводящие в заблуждение норму сбережений/
  остаток, пометить «доход не найден».
- Один снимок (нет истории) → «Динамика» просит сделать ещё хотя бы один разбор;
  советник не ссылается на прошлое.
- Мусор / разные валюты → фильтруем; MVP считает в рублях (одна валюта).
- localStorage недоступен/переполнен → работаем в памяти на сессию, честно
  предупреждаем, что история не сохранится.
- Дубль снимка за один период → предупредить/заменить.

## 10. Тестирование

- **Ядро** (`analyzer.js`, `advisor.js`) — юнит-тесты чистых функций на
  фиксированных наборах транзакций: агрегаты, score, флаги, рекомендации, ответы
  советника. Детерминированно, гоняется в `node`.
- **Парсер CSV** — тесты на разных форматах (разделители, заголовки, суммы с
  пробелами/запятыми, дедуп).
- **UI/флоу** — ручная проверка в браузере (preview-инструменты): вход → разбор
  → динамика → советник; светлая/тёмная тема; мобильный вид.
- Крайние случаи из §9 — как тест-кейсы.

## 11. Монетизация (имитируется в прототипе)

- **Free:** разбор по 1 выписке/мес, оценка здоровья, базовые рекомендации,
  советник ограниченно (~5 вопросов), история — последние N снимков.
- **Premium:** разборы и советник без лимита, полная история/динамика, экспорт
  отчёта в PDF, углублённые рекомендации.
- Реальная оплата (IAP/платёжный шлюз) — на этапе бэкенда, вне текущего MVP.

## 12. Дальнейший путь (вне MVP)

- Подход B: аккаунты + бэкенд → история и память советника между устройствами.
- Опционально LLM-советник (гибрид: цифры детерминированно, формулировки — модель).
- Экспорт отчёта в PDF, динамика за длинный период, сравнение с «нормой».
- Нативное iOS-приложение (по отдельному ТЗ).
